# E1 (add a Rosenbrock parameter set) and E2 (replace the step-size controller), nine Tier 1 entries

Read-only, from the worktrees at `~/NSF-NCAR/tier1-work/verify/<run>/clang/<run>/` and MICM at
`~/NSF-NCAR/ODE/benchmarks/micm/`. Line numbers are those of the files as checked out. An "edit
site" is a file-and-function that must change for the library to offer the feature; the benchmark
line that selects the method is listed separately, as the brief asks whether the benchmark needs
changes.

Two facts shape the ratings:

1. **RODAS3 already exists in MICM and in every entry.** MICM's
   `FourStageDifferentialAlgebraicRosenbrockParameters`
   (`include/micm/solver/rosenbrock_solver_parameters.hpp:309-356`: a = 0,2,0,2,0,1;
   c = 4,1,-1,1,-1,-8/3; m = 2,0,1,1; e = 0,0,0,1; alpha = 0,0,1,1; gamma = 0.5,1.5,0,0;
   new-function flags T,F,T,T; order 3) is, coefficient for coefficient, KPP's RODAS3 of Sandu et
   al. (1997). Every entry carries it as its four-stage DA set. E1 is therefore judged as "add a
   new four-stage set with its own tables, flags and order, selectable beside the five", which is
   what RODAS3 would have required; the mechanics are identical.
2. **What E2's controller needs.** MICM's controller is the factor
   `0.9·err^(-1/order)` clamped to `[0.2, 6]` plus two post-rejection rules (no increase after a
   rejected step; factor 0.1 after two rejections, `rosenbrock.inl:230-283`). A PI controller
   needs the previous accepted step's error and size and must replace those rules. Seven entries
   expose a callback that returns a factor from the current error only (astra-xhigh's also receives
   `h`); none passes the accept/reject outcome, and every entry keeps the post-rejection rules in
   the integrator. So the callback alone gives an approximate PI controller (it must infer
   acceptance from `err < 1` and track its own history); a faithful replacement also edits the
   accept/reject branch. That caps a hook entry at 4; the differences among them are where the
   controller's state can live (per group or not) and whether the hook is tested.

Backward Euler, in every entry as in MICM, advances with a fixed list of step reductions
(`time_step_reductions`), not an error-based controller; it is not a second copy of the controller
logic and is not counted below.

## Defects and findings noticed on the way

1. **luna-max, stage-reuse chaining** (`src/solver.c:713-728`, copy at 726-727). The copy of the
   current forcing into the next stage's K vector, made when the next stage reuses the function
   evaluation, is inside the `if (p->new_function_evaluation[stage])` branch; MICM's
   (`rosenbrock.inl:165-167`) and every other entry's is outside it. For a parameter set with two
   consecutive reuse stages the second reuse stage would start from a stale vector. None of MICM's
   five sets has such a pattern (ROS3 `{T,T,F}`, ROS4 `{T,T,T,F}`, RODAS3 `{T,F,T,T}`, the others
   all `T`), so no test can reach it. Sure of the reading of the code (the brace at 728 closes the
   branch); the consequence follows directly; not run.
2. **luna-xhigh, three-stage `e[1]`** (`src/chem.c:197`): `-2.907955871680469821793236208017`
   against MICM's `-0.29079558716805469821718236208017e+01`
   (`rosenbrock_solver_parameters.hpp`, three-stage set) — a digit dropped in transcription
   ("…16805469…" became "…1680469…"), relative difference 2.7e-14, a different double. It perturbs
   only the embedded error estimate at that level; the entry passed the 1e-10 gate. Certain of the
   text (compared programmatically); the numerical effect is negligible.
3. **luna-high, silent fallback** (`src/solver.c:236-250`): `chem_rosenbrock_builtin_parameters`
   returns the three-stage set for any enum value outside the five, without an error. Certain.
4. **luna-high, two Rosenbrock integrators** (`src/solver.c:488-690` generic single-cell;
   `767-945` grouped, hard-coded three-stage): the TS1 benchmark exercises only the second, while
   the parameter-set API and most of `tests/test_core.c` exercise the first. Certain.
5. **RODAS3 is MICM's four-stage DA set** (`rosenbrock_solver_parameters.hpp:309-356`), so the
   literal exercise would duplicate an existing table in every entry; the report treats E1 as a new
   four-stage set with its own tables and flags. Confident from the coefficient-by-coefficient
   match with KPP's `Rodas3`.
