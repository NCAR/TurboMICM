# Test-port fidelity, sample T1

Six of MICM's 680 cases traced through the nine Tier 1 entries, at each entry's
final commit (`~/NSF-NCAR/tier1-work/verify/<run>/clang/<run>/`): sol-high
1d944f43, sol-xhigh 171f54a4, sol-max 001fb64b, astra-high 4055d7c5,
astra-xhigh fbd365cf, astra-max 0dc7f67e, luna-max da2d722b, luna-xhigh
ada55d5f, luna-high d3c2480f. MICM paths are under
`~/NSF-NCAR/ODE/benchmarks/micm/test/`. Entry paths are relative to the
entry's root. Nothing was built or run.

Grades: F faithful, P partial, S surrogate, M mapped only, N/A as the brief
defines them. Two conventions applied throughout:

- Every entry replaced MICM's C++ random engines with its own generator. A
  substitute of the same distribution, size and density counts as the same
  input; a different distribution or density counts as "different inputs" (P).
- MICM's C++ policy variants (Doolittle/Mozart, in-place/separate, vector
  width L, CSR/CSC) are noted in each line. They lower a grade only when the
  entry runs fewer Rosenbrock methods than MICM, or when the id's name is the
  varied dimension ("Vector…") and the entry varies nothing in its place.

† luna-high prints every PASS line from a fixed list once one program,
`bin/test_core`, has exited 0; no id selects a check. Its grades are for the
nearest check in `tests/test_core.c`, and the dagger marks that the id's
verdict does not depend on that check alone.

## Runners: how `make test-cpu` becomes 680 lines

**sol-high.** `Makefile:65-66` runs `tests/run_cases.py`. It reads
`tests/cases.txt` (`run_cases.py:41-44`) and, for each id, looks up a Python
function in `PYTHON_CASES` by the full id or by `Suite.Test` (`:47-48`); the
function runs and any exception is a FAIL, otherwise `PASS reference
assertions` (`:51-56`). Ids not in Python fall back to a registered C program,
`bin/test_rates <name>` (`:57-60`); unmatched ids print `FAIL case port
pending` (`:61-62`); N/A comes from `tests/not_applicable.json` (`:40,49-50`).
Each module registers functions per name with a `case()` decorator or by
building dicts from name lists (`tests/test_linear.py:161-175`,
`tests/test_chapman.py:133-142`), so one function may serve several ids but
is selected by the id and branches on it.

**sol-xhigh.** `Makefile:64-66` runs `tools/test_configuration.py` and then
`bin/test_cpu tests/cases.txt`. `tests/runner.c:15-30` reads each id, splits
`suite.test`, and calls 22 dispatchers in turn until one returns a value other
than 2 (`:31-73`); 0 prints `PASS assertions verified`, 3 prints N/A with one
fixed reason, 2 prints `FAIL port not implemented`, 1 `FAIL assertion failed`
(`:75-89`). Dispatchers match by `strcmp(suite, …)` and `IS(test)`
(`tests/test.h:28`); `CHECK`/`NEAR` return 1 on the first failed assertion
(`test.h:9-27`). One id, one C code path, selected by name.

**sol-max.** `Makefile:52-53` runs `tests/run.py`, which reads
`case-list.txt` and calls `CASES.get(identifier)` with the id (`run.py:35-46`);
PASS `assertions passed`, `NotApplicable` → N/A, any exception → FAIL, no
function → `FAIL case port is not implemented` (`:43-51`). `harness.case`
registers full ids and raises on duplicates (`tests/harness.py:11-18`). Several
ids may share one function that branches on the id
(`tests/chapman_cases.py:156-158`), and the LU and linear-solver ids are
registered by scanning the case list (`tests/linear_cases.py:139-141`).

**astra-high.** `Makefile:52-53` runs `tools/run_tests.py`, which runs
`bin/test_cpu` once (`run_tests.py:18`). `tests/main.c:4-30` calls 24 suite
functions; every case is a `RUN(id, call)` (`tests/test.h:12`) that zeroes
`test_failures`, runs the call, and prints `<id> PASS original checks passed`

(`run_tests.py:20-25`), merges the tutorial programs (`:26-29`) and prints the
680 ids in `tests/cases.txt` order, with `FAIL case port pending` for any id

assembled from suffix arrays (`tests/test_sparse.c:130-154`).

**astra-xhigh.** `tools/test_registry.py:8-17` scans `tests/test_*.c` for

(`generated/test_registry.inc`, `Makefile:45-46`). `tests/main.c:9-24` reads

**astra-max.** `Makefile:88-90` runs `bin/test_native_cpu extensions`

## Case 3: `lu_decomposition_mozart_in_place:LuDecompositionMozartInPlace.RandomMatrixVectorOrdering`

**MICM.** `unit/solver/test_lu_decomposition_mozart_in_place.cpp:56-62` runs

`unit/solver/test_lu_decomposition_in_place_policy.hpp:120-185`: a 10×10
pattern with the full diagonal plus one coin flip per entry
(`uniform_int_distribution(0,1)` on `default_random_engine`, `:123-137`);

blocks (`:145-158`); `Decompose` in place (`:160-178`); `CheckResults`
