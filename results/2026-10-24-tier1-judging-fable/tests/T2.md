(`~/NSF-NCAR/tier1-work/verify/<run>/clang/<run>/`) and from MICM e15898ce
(`~/NSF-NCAR/ODE/benchmarks/micm/test/`). Nothing was built or run. Paths are

Grades follow the brief: **F** faithful (same scenario, same assertions, through
the C API), **P** partial (same scenario, fewer or weaker assertions, different
inputs, looser tolerance), **S** surrogate (a different or shared check stands
in), **M** mapped only (verdict from a list, no check found), **N/A** (entry
marks it so). One rule applied throughout: when an id's verdict is the exit
status of a binary shared by many ids (so the id cannot fail or pass on its
own), the grade is S even if a matching check exists inside that binary; the
check is cited in the explanation.

## The runners

**sol-high.** `make test-cpu` (`Makefile:65-66`, extra prerequisites at 71, 83,
87, 95) runs `python3 tests/run_cases.py`. For each line of `tests/cases.txt`
(680 ids, reference order) the runner consults `tests/not_applicable.json` (5
ids, each with a reason), else a Python callable in `PYTHON_CASES` keyed by the
full id or by `Suite.Test` (imported from 21 `tests/test_*.py` modules,
`run_cases.py:6-28`; PASS unless the callable raises), else runs
`bin/test_rates <name>` as its own process when the name is in that binary's
`--list` (`run_cases.py:37-38, 57-60`; `tests/rate_cases.c:148-204`, 31
names), else prints `FAIL case port pending` (`run_cases.py:41-64`). Each id
thus runs a check selected by its name; several callables are `partial`s of one
function with case-specific arguments. A supplemental line and a nonzero exit on
any FAIL follow (`run_cases.py:65-72`).

**sol-xhigh.** `make test-cpu` (`Makefile:64-66`) runs
`tools/test_configuration.py`, then `bin/test_cpu tests/cases.txt`.
`tests/runner.c:3-94` reads the case file; a program id goes to
`test_tutorial(id)`, a gtest id is split into suite and test and offered to 23
suite functions in turn (`test_rate` … `test_stiff`, `runner.c:31-73`), each
returning 0 PASS, 2 not handled (next function; if none handles it, `FAIL port
not implemented`), 3 N/A (one fixed reason, `runner.c:82`), or 1 `assertion
failed`. Inside a suite function the test name selects the branch (`IS(name)`,
`tests/test.h:28`) and `CHECK`/`NEAR` return 1 at the first failed assertion
(`test.h:9-27`), so each id has its own check, with fixture code shared between
neighbouring names.

**sol-max.** `make test-cpu` (`Makefile:52-53`) runs `python3 tests/run.py`,

register one function per full id and reject duplicates
(`tests/harness.py:11-18`). For every line of `case-list.txt` the runner calls
the registered function with the id (PASS; FAIL on an exception; N/A when it
