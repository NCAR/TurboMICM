# Exercises E1 and E2, on paper, for the nine Tier 1 entries

This works out, from the code as it stands, what each change would take. Each entry was read at its final commit under `~/NSF-NCAR/tier1-work/verify/<run>/clang/<run>/`. Paths are relative to that root unless they name MICM, which is at `~/NSF-NCAR/ODE/benchmarks/micm/`. Nothing was built, run or edited.

## Common ground

### MICM, for comparison

**Parameter sets.**
- `RosenbrockSolverParameters` (`include/micm/solver/rosenbrock_solver_parameters.hpp:22-75`) holds fixed arrays: 6 stages and 15 lower-triangular coefficients (`:51-72`).
- Five factory functions build MICM's sets.
- The four-stage differential-algebraic set (`:308-355`) has RODAS3's coefficients:

  | Field | Values |
  |---|---|
  | a | 0, 2, 0, 2, 0, 1 |
  | c | 4, 1, −1, 1, −1, −8/3 |
  | m | 2, 0, 1, 1 |
  | e | 0, 0, 0, 1 |
  | new-function flags | 1, 0, 1, 1 |
  | alpha | 0, 0, 1, 1 |
  | gamma | 0.5, 1.5 |
  | estimator order | 3 |

**Stages.**
- One loop runs over `stages_` (`include/micm/solver/rosenbrock.inl:140-195`).
- When a stage reuses the previous function value, it starts from a copy of that stage's raw forcing, taken before the stage adds its c-terms and solves (`:165-168`).
- Only `gamma_[0]` enters the solve; `alpha_` is not used.

**Controller.** It is inline in `Solve`:
- The factor is `min(6, max(0.2, 0.9 / err^(1/estimator)))` (`:229-235`).
- A NaN or Inf error stops the solve (`:240-247`).
- A step is accepted if `err < 1` or `H < h_min`. The new step is then clamped to `[h_min, h_max]`, and it cannot grow right after a rejection (`:250-264`).
- On a rejection, the second rejection in a row sets `H *= 0.1`, and the Jacobian is rebuilt for the in-place LU (`:265-290`). Rejections are counted only after the first acceptance (`:276`).
- Each call restarts `H` from `h_start` (`:33-36`), which defaults to 1e-6 of the interval (`rosenbrock.hpp:61-62`).
- The error norm is floored at 1e-10 with `std::max`, which passes a NaN through (`:401`).

**Backward Euler** has its own convergence-based rules. On a failure, `H *= time_step_reductions[n]` (0.5, 0.5, 0.5, 0.5, 0.1); after two successes, H doubles (`backward_euler.inl:166-187`).

**Tests per set.**
- Every analytical test runs all five sets (`test/integration/test_analytical_rosenbrock.cpp:111-120`).
- One Chapman regression per set compares with a hand-coded three-stage solver at a relative tolerance of 1e-4 (`test/regression/RosenbrockChapman/regression_test_solve.cpp:12-49`; `regression_test_solve_policy.hpp:9-68`).

### Conventions used here

**Counting edit sites.**
- In the library and the benchmark: one site per function, table or declaration, however many lines change in it. A new function counts as one site.
- In tests: one site per test file or data list. A case-id registry that goes with a test counts with that test.
- Counts read "total (library + benchmark + tests)".

**E1 ratings.**
- Ratings cover the library and the code TS1 runs.
- The six-stage limit is not held against any entry: it is explicit and checked in all nine.
- A limit the new set does not reach lowers a rating by one only if it is unchecked and silently gives wrong results.
- The benchmark edit is the same everywhere.
- The test work only breaks ties in the ordering.

**E2 ratings.** A PI controller needs three things: the current step size, and the previous accepted step's size and error. Gustafsson's predictive controller and Söderlind's H211b are the examples here; H211b's factor is `safety · err^(−1/4k) · err_prev^(−1/4k) · (h/h_prev)^(−1/4)`, with k the estimator order, clamped to `[factor_min, factor_max]`.

| Rating | Meaning |
|---|---|
| 5 | The hook already receives enough, and TS1 goes through it. |
| 4 | TS1 goes through the hook, but its signature must grow: the typedef, the default, one call site, and the history kept in the one integrator. |
| 3 | There is no hook, and the accept/reject logic is written out in more than one integrator. |
| 2 | The function TS1 runs has its own copy of the controller, specialized to ROS3, apart from the general path. |

## Defects found

Each defect was checked against the code as cited. Effects on TS1 are inferred, not measured.

1. **A NaN error estimate is accepted as a tiny error** in luna-max, luna-xhigh and luna-high.
   - Each floors its error norm with C's `fmax`, which returns the non-NaN argument: luna-max `src/solver.c:80`; luna-xhigh `src/chem.c:1045` (grouped) and `:837` (DAE); luna-high `src/solver.c:655` (single-cell) and `:907` (group).
   - A NaN norm therefore comes back as 1e-10. The step is accepted, and the next step may be up to 6 times larger.
   - The `!isfinite` checks that follow cannot fire for a NaN: luna-max `src/solver.c:767`; luna-xhigh `src/chem.c:1206`, `:1478`; luna-high `src/solver.c:659`, `:916`.
   - MICM's `std::max` keeps the NaN and stops with `NaNDetected` (`rosenbrock.inl:240-243`, `:401`).
   - A NaN then surfaces only if it reaches an LU pivot check, and the clamp leaves NaN in place, since `NaN < 0` is false.
   - sol-high has the same floor (`src/rosenbrock.c:26`) but scans its arrays for non-finite values (`:99-101`); only direct callers of its public `chem_normalized_error` see 1e-10.
   - Confidence: high in the mechanism (C11 Annex F, `fmax`). There is no effect on TS1, which produces no NaN.
2. **luna-xhigh's ROS3 error coefficient** `e[1]` is `-2.907955871680469821793236208017` (`src/chem.c:197`); MICM's is `-0.29079558716805469821718236208017e+01` (`rosenbrock_solver_parameters.hpp:227`).
   - As doubles that is −2.90795587168047 against −2.907955871680547, a relative difference of 2.7e-14.
   - It is in the default set TS1 runs. The other eight entries have MICM's value.
   - Confidence: high that the value differs. Its effect on the 1e-10 gate is negligible: it changes the error estimate by about 1e-14 relative.
3. **luna-max's backward Euler has no step-size control.**
   - It takes one Newton-solved step over the whole interval and fails if Newton does not converge (`src/backward_euler.c:69-114`).
   - MICM cuts the step by 0.5, 0.5, 0.5, 0.5, 0.1 on failures and doubles it after two successes (`backward_euler.inl:166-187`).
   - Confidence: high.
4. **luna-max mishandles two reused stages in a row** (`src/solver.c:713-728`). The next stage's copy is made only after a new evaluation, so such a set would solve a stage from stale data. This is latent: no current set, and not RODAS3, has those flags. Confidence: high.
5. **luna-high's documentation describes one generic path.** DESIGN.md:80-82 says so for parameter sets, and DESIGN.md:108-112 says the controller can be changed independently. The function TS1 runs has its own three-stage coefficients and controller (`src/solver.c:796-935`). Confidence: high.
6. **Smaller items in luna-high.**
   - An enum value with no branch silently yields ROS3 (`src/solver.c:236-250`).
   - Rejections are counted before the first accepted step (`:675`, `:933`), where MICM counts only after one (`rosenbrock.inl:276`). This affects statistics only.
   - Confidence: high.
