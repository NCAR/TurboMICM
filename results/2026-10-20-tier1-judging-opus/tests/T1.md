## How the grades were applied

- **Random inputs.** A different random-number generator in place of MICM's is accepted when sizes and distributions match, because MICM's own inputs are random by construction (its `std::default_random_engine` is implementation-defined). Each such case says so.
- **Tolerances.** A stricter tolerance does not lower a grade.
- **Configurations count as assertions.** MICM's configurations are its parameter sets, LU algorithms, storage and vector widths. A check that covers fewer of them than the entry's C API can select is P. Variants the API cannot express, such as vector widths for a single cell in a layout with no padding, are not held against the entry.
- **Case 2 is about storage.** Its subject is the contrast between a solver with separate L and U and an in-place solver. A comparison of two in-place runs is P, even if they use different algorithms.
- **P or S.** P means the same scenario with something weaker. S means the check stands in from elsewhere: it exercises different code than the one MICM's case tests, uses a different scenario, or is a generic check shared by many ids.
- **luna-high.** Every luna-high PASS line comes from a list (see its runner below). Its grades describe the check in `tests/test_core.c` that corresponds to the case, and M marks a case with no such check.
