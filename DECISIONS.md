# Decisions

- Store the TS1 translation as normalized JSON generated by
  `tools/import_ts1.py`, then generate C tables during the build. This keeps
  configuration parsing and mechanism construction out of the executable.
- Record phase metadata (`third_body`, molecular weight, and diffusion) because
  surface rates require diffusion data and the third body contributes air
  density rather than a state concentration.
- Represent each surface reaction's two custom inputs as labeled effective
  radius and particle number concentration parameters. Preserve the reaction
  probability as the rate constant's scale.
- Order solver variables with the same diagonal Markowitz fill heuristic used
  by the reference builder. Keep output and input mapping name-based so the
  internal permutation does not change the CSV interface.
- Cache rate constants and matrix workspaces per solver workspace because
  temperature, pressure, and custom parameters stay fixed through a cell's
  integration.
- Read JSON with the Python standard library and YAML with the pinned PyYAML
  package in the local prefix environment.
- Keep C11 and OpenMP selection in the Makefile; optimization remains controlled
  by `OPTFLAGS`.
- Store rate parameters in a fixed 24-double reaction record, enough for the
  16-coefficient Taylor series and its six base values. Lambda rates use a C
  function pointer with temperature, pressure, density, and parameter inputs;
  a configuration without a C callback evaluates to zero until linked by the
  mechanism builder.
- Return a nonzero C status when surface-rate metadata lacks molecular weight
  or diffusion data, matching the construction-time error in MICM.
- Represent parameterized gas species with an explicit flag and density factor.
  Fold `(air_density * factor)^coefficient` into each reactant rate constant;
  keep the species as an output row but exclude it as a kinetic dependency.
- Use one contiguous cell group per requested worker in the TS1 benchmark. Cells
  in a group share the Rosenbrock step controller and normalized error norm, as
  in the reference benchmark; each cell still has its own rate constants,
  forcing, Jacobian, and factorization.

- Mark the five `ViewCategorySFINAE` cases N/A because they inspect C++
  template substitution and type categories, which have no C equivalent. The
  CPU `ProcessSetAlgebraicVariables.CudaMatrix` case is ported through masked C
  forcing and Jacobian accumulation. Constraint residual primitives and
  algebraic projection are also available through the C API.

- Represent linear and equilibrium constraints as caller-owned C records with
  species indexes and stoichiometric terms. Keep residual, algebraic-mask,
  Jacobian-pattern, and negative-Jacobian evaluation separate from solver
  integration so these primitives can be validated independently. Equilibrium
  constants use a van't Hoff correction from a reference temperature.
  The optional constrained solve projects algebraic variables with a Newton
  solve before integration and after accepted steps; it does not yet apply a
  full Rosenbrock DAE stage formulation.

- Represent basic dense matrix access with a non-owning strided C view rather
  than an owning template type. Keep allocation with the caller and validate
  dimensions and strides at the API boundary.
  Lane-packed dense views carry their group width at runtime; tests compare
  widths 1, 2, 4, and 8 against identical logical row-major values.
  A const-source row callback handles read-only matrices and one-column vector
  views; row-count mismatches are rejected at invocation.

- Represent sparse matrices as non-owning block CSR views. A block shares one
  sorted, duplicate-free row/column pattern; values are contiguous block-major
  slices, and operations return status codes for missing structural entries.
  Entry views span blocks with an explicit stride; block callbacks can combine
  entries from matrices with different sparsity patterns when block counts match.

- Store optional species properties in caller-owned tagged records. Typed C
  getters report missing properties separately from type mismatches, avoiding
  unchecked casts from the C++ property API.
  Species record copy construction and assignment use C value copies; names and
  property arrays remain borrowed caller-owned data.

- Give the independent C library an initial version of `0.1.0+0` and expose the
  string and numeric components through `chem_version*` functions.

- Expose runtime state through a non-owning cell-major view over caller-provided
  arrays. Batch species and custom-parameter updates validate labels and cell
  counts before changing data, and return status codes instead of throwing.

- Mark the four State copy/move cases N/A. The C state API is a non-owning view,
  so it has no deep-copy or move constructor behavior to reproduce.

- Implement matrix logical OR/AND reductions with caller-supplied predicates and
  a strict reduction that visits each logical entry once. Strided views expose
  no padded entries, so strict traversal is the ordinary bounded row/column loop.
