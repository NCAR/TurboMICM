# Decisions

- Store the TS1 translation as normalized JSON generated by
  `tools/import_ts1.py`, then generate C tables during the build. This keeps
  configuration parsing and mechanism construction out of the executable.
- Record phase metadata (`third_body`, molecular weight, and diffusion) because
  surface rates require diffusion data and the third body contributes air
  density rather than a state concentration.
- Represent each surface reaction's two custom inputs as labeled effective
  radius and particle number concentration parameters. Preserve the reaction
  probability as the rate constant's scale.
- Order solver variables with the same diagonal Markowitz fill heuristic used
  by the reference builder. Keep output and input mapping name-based so the
  internal permutation does not change the CSV interface.
- Cache rate constants and matrix workspaces per solver workspace because
  temperature, pressure, and custom parameters stay fixed through a cell's
  integration.
- Read JSON with the Python standard library and YAML with the pinned PyYAML
  package in the local prefix environment.
- Keep C11 and OpenMP selection in the Makefile; optimization remains controlled
  by `OPTFLAGS`.
- Store rate parameters in a fixed 24-double reaction record, enough for the
  16-coefficient Taylor series and its six base values. Lambda rates use a C
  function pointer with temperature, pressure, density, and parameter inputs;
  a configuration without a C callback evaluates to zero until linked by the
  mechanism builder.
- Return a nonzero C status when surface-rate metadata lacks molecular weight
  or diffusion data, matching the construction-time error in MICM.
