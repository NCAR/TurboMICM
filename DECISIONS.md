# Decisions

- The public library uses C11 and double precision. It has no runtime dependency on the reference implementation, Python, or a configuration parser.
- Configuration parsing and optional specialization run in the private prefix environment at build time. Both generated and manually built mechanisms use the same public mechanism and solver interfaces.
- The reference case identifiers are retained verbatim. C++ ownership and exception tests will exercise C allocation, copying, validation, and error returns where meaningful; any inapplicable language-only case will have an explicit reason.
- Source formulas and numerical coefficients are translated from the provided reference snapshot. Attribution is preserved in translated source files.
- TS1 format extensions are `reactant sequence` (ordered species names), `product sequence` (ordered objects with `species` and `yield`), species `parameterization: third body`, and top-level `initial state` containing `temperature`, `pressure`, `concentrations`, and `rate parameters`. Ordered sequences preserve repeated species and floating-point accumulation order without ambiguity. `USER_DEFINED` with `MUSICA name` and `scaling factor` represents the existing user-rate type directly. Surface reactions retain their source label and SI properties. All rate coefficients in the translated configuration are already in SI units, as in the C++ declarations.
- Utility matrix elements are double precision, including tests whose C++ template uses integer elements; all integer test values are exactly representable. Array views carry an explicit read-only flag rather than relying on C++ template deduction. Four compile-only SFINAE cases and one compile-only grouped category-tag case are N/A; the runtime vector sum case is retained.
- Randomized numerical tests use deterministic Python seed 1 and the reference lognormal distribution parameters, dimensions, and tolerances. C++ default engines and normal distributions do not define a cross-standard-library sequence; fixed Python fixtures make the port's tests reproducible across compiler/OS combinations. Explicit numerical fixtures retain their original values.
- The reference's C++ template combinations become runtime C layouts and callback choices. Array policy tests exercise groups 1, 2, 3, and 4 (plus other sizes where relevant), both sparse orderings, and padding. Solver cases use species-major storage with contiguous cells, all parameter sets requested by each case, and both LU algorithms. Duplicate template instantiations do not require duplicate integrators in C.
- The example files use molecule/cm3 rate coefficients; their by-hand tutorials explicitly convert these to mole/m3 units. The reader therefore defaults to those example units, converting the pre-exponential factors according to reactant order and falloff type. TS1 now explicitly specifies `concentration units: mol m-3`, since its source declarations are already converted. The reader also accepts this setting per mechanism. Custom rate parameters, surface properties, and the `initial state` extension use SI values. A callback cannot be serialized; lambda rates remain a C builder feature.
- The examples label the surface process `C surface`, while the corresponding by-hand programs label it `C`. Configuration-equivalence tests set the appropriate surface parameter names in each state and compare all species, forcing, and Jacobian entries by species name. They run both generic and generated kernels through the same integrator, at a tighter 1e-10 relative/1e-30 absolute comparison bound.
- Tutorial output comparison is exact after removing measured elapsed time from `solver_configuration` and the concurrently interleaved startup diagnostics from `openmp_tutorial`. Solver counts, all concentration tables, labels, and array-order output are retained. Both the reference and C program must emit three thread-startup messages. The vectorized-matrix tutorial's initial `Converged` condition prevents its solve loop from executing; its port retains the resulting unchanged values and checks layout/order, as the original does.
- Chapman regression tests use an independent Python translation of the old fixed solver, including its own dense LU, scalar tolerance, step-size control, forcing, and analytical Jacobian. It is a test oracle only. The C solver always uses a generic code-built mechanism. The fixed solver's oversized Jacobian-vector result has fourteen unused zero entries; the C matrix product returns the nine meaningful species entries.
- The benchmark clamps differential variables after each complete solver call, as the reference solver facade does. Algebraic variables remain unclamped. This matters for the rate-constant tutorial's initially negative tiny intermediate and is verified by exact printed output.
- Runtime group scheduling is controlled with the standard OpenMP `OMP_SCHEDULE` setting. It defaults to static in the benchmark. Kernel chunking is exposed as a generator/build parameter because it controls compiler work and may affect speed, without affecting arithmetic order.
- Tier 2 uses the same configuration reader and symbolic Markowitz ordering as Tier 1. A second generator emits rate formulas, sparse Mozart factorization, triangular substitutions, and a three-stage integration loop. The numerical parameter table remains the library's single source; step length, tolerances, conditions, concentrations, and every custom parameter remain runtime data.
- The scenario runner shares CSV initialization/output code with the benchmark. It retains base photolysis parameters after all CSV overrides, multiplies every label beginning with `j` by the interpolated factor at each step, and recalculates rates. Snapshot I/O occurs between timed batches of solver steps. There is no scenario warm-up. Consecutive groups default to 32 cells, with runtime overrides supported for both drivers.
- Specialization tests include all Tier 1 configuration mechanisms, mixed source/sink and duplicate-term edge cases, and a build-generated TS1 variant that changes a rate coefficient and adds a reaction. They compare rates, forcing, Jacobians, factorizations, direct solves, and integrated concentrations to the generic library with a strict `1e-10 * abs(reference)` bound; expected zeros must match exactly.
- Cell tiles are an execution/storage optimization inside an adaptive group. They complete independent cells' three Rosenbrock stages using a small packed workspace; the original group's species-major error sum determines one shared step length and acceptance decision. Tiles never create additional adaptive controllers. Packing keeps the full rate/concentration data at double precision. The unused three stage vectors provide scratch space when sufficient; other sizes use a checked allocation. Padding never enters the norm. Statistics count the same logical group operations as the reference, independently of tile size.
- Generated SIMD computation of the error terms retains a serial sum in the original species/cell order. First-write initialization of chemistry outputs performs `0.0 +/- term` for the first contribution, keeps subsequent contributions ordered, and explicitly zeros untouched entries (including symbolic fill). These transformations do not aggregate duplicate chemical terms or reassociate stoichiometric sums.
- Both generators emit Make dependency files for every recursively visited `camp-files` input. Empty input rules also permit removing a former include and its file together. The supplied GNU Make 3.81 compares whole-second timestamps; dependency regeneration was verified with input timestamps separated by a full second.
